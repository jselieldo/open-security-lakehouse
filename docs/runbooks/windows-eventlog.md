# Windows Event Log collector

The first Windows source uses Vector `0.61.0` (MPL-2.0) and its native
`windows_event_log` source. The version matches the server-side Vector image and
is intentionally pinned. Vector keeps checkpoints and its durable buffer below
`C:\ProgramData\OpenSecurityLakehouse\vector-data`.

## Security boundary

The OSL API remains loopback-only. Windows sends RFC 5424-compatible records over
mutually authenticated TLS to `192.168.3.120:6514`; Vector on the homelab then
authenticates to the internal ingestion API with its ingestion-only token. The
listener is CIDR-restricted and must never be exposed to the Internet. The Windows
collector verifies the OSL server certificate and presents its own dedicated client
certificate. Its private key is readable only by Local Service, Administrators and
SYSTEM.

## Install and validate

1. Download the pinned MSI from the official Vector repository:
   `https://install.datadoghq.com/vector/0.61.0/vector-0.61.0-x64.msi`.
2. Verify its SHA-256 before installation. The expected value for the 0.61.0
   x64 MSI is
   `3ac167f226204e141d164c6218ae54a2df77dda1b3322bef4b565d4066c4cfad`.
   The MSI does not carry an Authenticode signature, so a matching published
   checksum is mandatory.
3. Run the MSI as an administrator; the package rejects non-elevated installs.
4. Verify that the installed binary reports `vector 0.61.0`.
5. Confirm that `192.168.3.120` is still the homelab address and restrict
   `SYSLOG_ALLOWED_CIDR` in the homelab `.env` to `192.168.3.0/24`.
6. Copy only the Windows client files generated by the homelab into the ignored
   `data\mtls\clients\windows` directory: `ca.crt`, `client.crt`, and `client.key`.
   Never copy `ca.key` or either Linux or server private key to Windows.
7. From an elevated PowerShell in the repository, install the configuration and
   startup task:

   ```powershell
   Set-ExecutionPolicy -Scope Process Bypass
   .\scripts\install-windows-collector.ps1
   ```

Reading the Security channel requires an account with permission to read it. Do
not grant local administrator access solely for Vector. The installer runs the
scheduled task as the limited built-in `Local Service` identity and adds only
that identity to the built-in Event Log Readers group. It restricts the data
directory ACL to Local Service, Administrators and SYSTEM. The initial start
reads at most the previous hour and then resumes from durable per-channel
checkpoints. Event-data fields are limited to 4096 bytes and raw XML is disabled.

The installer validates all three certificate files, copies them into the protected
ProgramData directory, and validates the final Vector configuration before replacing
and starting the scheduled task. The collector also subscribes to Microsoft Defender and modern PowerShell
operational channels. A channel that does not exist on a particular Windows
edition is skipped without weakening the other subscriptions.

Server-side Vector flushes a batch after 100 events or two seconds, whichever
comes first. Do not reduce this to one event per request: doing so creates one raw
and one normalized object for every record and degrades investigation performance.
Linux, Windows and validation events use separate routes and disk buffers so a
batch can never mix source identities. Installations upgraded from the original
single sink may retain an unreferenced `osl_api` buffer directory; keep it for
forensic review until a deliberate recovery or retention decision is made.

## Register and verify the source

Register it from the homelab with an administrator access token:

```bash
curl --fail -X POST http://127.0.0.1:8000/api/v1/sources \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"source_id":"windows-workstation","source":"windows-eventlog","kind":"windows","hostname":"WINDOWS-HOSTNAME","display_name":"Windows workstation","expected_interval_minutes":60}'
```

Generate or locate a harmless Application event, then filter the OSL console by
source `windows-eventlog`, hostname and event type. Raw Windows fields remain in
the immutable raw object and in the normalized row's `raw_event_json`.

## Detection coverage

Versioned rules detect event 4625 bursts, account and group changes, service
installation (7045), Security log clearing (1102), Defender threat events and
PowerShell 4104 records containing `EncodedCommand`. Validation traffic must use
a harmless event ID that none of these rules match.

## Data minimization

Windows logs can contain usernames, process command lines, file paths and IP
addresses. Access them only through OSL roles, keep the API private, and apply a
retention policy before expanding collection to additional channels.
